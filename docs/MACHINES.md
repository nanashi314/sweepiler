# マシン言語（.imsg）とフレーム連結

テトリス以外のゲームや対話的なプログラムを、小さな言語`.imsg`で書けます。C風の言語MineC（`.mc`）もあります（[MINEC.md](MINEC.md)）。コンパイラは1ティック分の処理を普通の数字と地雷のフレームへ変換し、テトリスと同じ仕組み（入力マスの地雷、隣接フレームが共有する列、Displayウィンドウ）で動かします。

## 使い方

sweepilerのCODEタブのOPENで`.imsg`ファイルを開き、実行します（`examples/`のPaint、Catch、Pong）。サンプル一覧のプログラムはすべてMineCです。

初回のBuildは配置と配線に時間がかかります。結果は`%LOCALAPPDATA%\InfiniteMinesweeper\frames`に保存します。保存キーはネットリスト全体と配置の設定から作るので、プログラムを1文字でも変えれば作り直します。

## 言語

```text
display 6 8                # 画面（1..16 x 1..32）
input LEFT hold            # キー。hold は押している間、press は押すごとに1回
input A press
state x 3 = 2              # 状態：名前、幅（1..64ビット）、初期値
tick                       # 1ティックの処理
  if LEFT and x > 0
    x = x - 1
  elif A
    x = 0
  end
end
screen                     # tick の後の状態から画面を作る
  for i 0 5
    pixel i 7 = i == x
  end
end
```

| 文 | 意味 |
| --- | --- |
| `NAME = expr` | 状態または`let`の変数へ代入。幅に合わせて切り詰め／0拡張 |
| `NAME[expr] = expr` | 1ビットの代入。添字は変数でもよい（範囲外は無視） |
| `let NAME WIDTH = expr` | ブロック内の一時変数 |
| `if` / `elif` / `else` / `end` | 条件分岐。条件はすべて分岐前の値で評価します |
| `for NAME FIRST LAST` ... `end` | 定数範囲の繰り返し（展開）。式は括弧で囲みます |
| `pixel X Y = expr` | `screen`内で画素を設定。座標は定数。設定しない画素は0 |
| `at X Y` | 以降のゲートの配置位置の目安（任意） |

式には整数（10進、`0x`、`0b`）、名前、`NAME[expr]`、括弧、`+ - & | ^ ~`、定数の`<< >>`、比較`== != < <= > >=`、論理`and or not`を使えます。

- 算術は広い方のオペランドの幅で折り返します。比較と論理演算の結果は1ビットです。
- 整数リテラルとループ変数には幅がなく、もう一方のオペランドの幅に合わせます。定数どうしの計算は正確に行います。

## 仕組みと検証

- **コンパイラ**：プログラムを記号実行し、各分岐の結果をマルチプレクサで合流させて、NORのネットリストにします。定数は畳み込み、同じゲートは共有します。
- **参照インタプリタ**：同じ構文木を整数で実行する独立した実装です。検査だけに使い、生成・Solve・表示には使いません。
- **配置**：焼きなましで配線長を最小化します。`at`があればその位置から局所的に改善します。配線長からゲート間隔を決めます（[MINEC.md](MINEC.md)）。配線は`GridLayout`（4マス間隔の格子、Thieme/Basten交差、PathFinder）です。
- **フレームの連結と求解**：テトリスと同じです。毎ティック、通常の推論だけで全マスが確定した場合だけ受け入れます。出力が定数になるときは、値0の数字マスを1つ置いてそこから配線します。

| 検査 | 結果 |
| --- | --- |
| コンパイラ対インタプリタ | Paint、Catch、Pong、全演算子のプログラムで各3,000ティック、711,006回の比較が一致 |
| エラー | 未定義の名前、入力への代入、画面外の画素、変数のシフト量、`end`の不足、入力なしを行番号付きで拒否 |
| Paint（492 NOR） | 1635×995マスのフレーム（配置約1秒）。300ティックで表示と状態が参照と一致（平均18 ms） |
| Catch（330 NOR） | 771×707マス。300ティックで一致（平均8 ms） |
| Pong（345 NOR） | 755×739マス。300ティックで一致（平均9 ms） |
| フレームの継ぎ目 | 各プログラムで2フレームを1枚の通常の盤面として解き、2ティック目の表示が参照と一致 |

## 制限

- 1ティックの処理は有限の組合せ回路です。`for`は定数範囲だけで、無限ループや再帰はありません。
- 変数は1..64ビットの符号なし整数です。乗算・除算はなく、シフト量は定数です。
- 入力は6個まで、画面は16×32までです。
- ゲート数が多いと配置に時間がかかり、フレームも大きくなります（目安は1ゲートあたり約1,600〜3,300マス）。
