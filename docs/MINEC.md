# MineC：Cライクなマシン言語

MineCは、連結フレーム（[MACHINES.md](MACHINES.md)）で動くプログラムをC風に書く言語です。コンパイラは1ティック分の処理をNORのネットリストにし、普通の数字と地雷だけのフレームに配置します。盤面が計算した表示をDisplayウィンドウが映し、キー入力は入力マスの地雷になります。

sweepiler（`sweepiler.exe`、[SWEEPILER.md](SWEEPILER.md)）では、サンプル19本（入門の6本を含む）がすべてMineCで、CODEタブのエディタ（色分けと補完）で編集して実行できます。言語のリファレンスはジャンルとトピックの木で、別のウィンドウに開きます。自分で書いた`.mc`ファイルは、CODEタブのOPENで開けます。

## 例

```c
#display 8 8                 // 画面（1..32 x 1..32）
input hold left;             // 押している間 1
input press fire;            // 押すごとに1ティックだけ 1
const int N = 4;             // コンパイル時定数

uint3 x = 2;                 // グローバル変数＝ティック間で保たれる状態
bool shots[8];               // 配列も状態

int8 clamp(int8 v) {         // 関数はインライン展開（再帰なし）
    return v < 0 ? 0 : v > 7 ? 7 : v;
}

void tick() {                // 1ティックの処理
    if (left) x--;
    if (fire) shots[x] = true;
    for (int i = 0; i < 8; i++)   // 定数範囲のループは展開
        if (i >= N) break;
}

void draw() {                // tick の後の状態から画面を作る
    for (int y = 0; y < 8; y++)
        for (int i = 0; i < 8; i++)
            pixel(i, y, shots[i] && y == x);   // 座標は変数でもよい
}
```

## 言語

| 項目 | 内容 |
| --- | --- |
| 型 | `bool`、`uintN`、`intN`（N=1..64、2の補数）、`int`（=`int32`） |
| 文 | 宣言、`=` `+=` `-=` `*=` `/=` `%=` `&=` `|=` `^=` `<<=` `>>=`、`++` `--`、`if`/`else`、`for`、`break`、`continue`、`return`、ブロック、関数呼び出し |
| 式 | Cの演算子（代入・カンマを除く）、キャスト`(uint8)e`、`?:`、配列`a[i]`（添字は変数でもよい） |
| 組み込み | `pixel(x, y, v)`（座標は変数でもよい）、`at(x, y)`（以降のゲートの配置の目安、任意） |
| 最上位 | `#display W H`、`input [hold\|press] name;`（1..6個）、`const`、グローバル変数・配列、関数、`void tick()`（必須）、`void draw()` |

意味はCに合わせ、ハードウェアで決まらない部分だけを次のように定めています。

- 算術は2つのオペランドの共通の型で折り返します。共通の型は広い方の幅で、どちらかが符号付きなら符号付きです。各オペランドは自分の符号で拡張します。整数リテラルは幅を持たず、もう一方のオペランドの型になります。
- `&&`と`||`は短絡しません（両辺を評価します）。
- 除算は0方向への丸めです。0で割ると商は全ビット1、余りは被除数です。
- シフト量が幅以上か負なら、結果は0（右算術シフトは符号で埋める）です。
- 範囲外の添字の読み出しは0、書き込みは無視します。
- `for`の初期値・条件・増分はコンパイル時に決まる必要があります（展開します）。`while`と再帰はありません。1ティックは有限の組合せ回路です。

## コンパイラ

- **述語つき実行**：分岐の両側を記号実行し、代入は「この経路が有効なら新しい値、そうでなければ元の値」というマルチプレクサになります。`return`、`break`、`continue`は経路を無効にする信号で表します。
- **変数の添字と座標**：添字の各値に一致する信号を、上位と下位に分けた2つのデコーダの項の積として必要な項だけ作り、共有します。定数との`==`も同じ項を使います。
- **加算と乗算**：3項以上の`+`/`-`の連鎖と乗算の部分積は、列ごとに全加算器で圧縮する多入力加算にします。同じ値の2乗は部分積を半分にします。
- **定数畳み込みと共有**：NorBuilderが定数を畳み込み、同じゲートを共有します。
- **経路の条件が同じ局所変数**：局所変数（引数を含む）を宣言したときと同じ経路の条件での代入は、マルチプレクサなしで値を置き換えます。条件が偽なら、その変数を読む計算はどれも外に影響しないからです。関数の最初の`return`も同様です。
- **使われない計算の除去**：どの出力にもつながらないゲートを最後に取り除きます。

## 配置と配線の高速化

| 変更 | 効果 |
| --- | --- |
| 焼きなまし配置 | ゲートを格子上で入れ替え、全ネットの半周長を最小化します。状態入力は左端、状態出力は右端、画素出力は下端へ引きます。`at`の目安がある回路はそこから局所的に改善します |
| 配線密度に応じた間隔 | 配置後の配線長から、配線が格子面積の約13%以下になるようゲート間隔を広げます（例：Snakeは64×52、Lifeは68×52）。密すぎて収束しない配線を避けます |
| 配線ルータ | 全ネットの再配線を混雑が広い間だけにし、収束が止まると再配線範囲を広げます |
| 通常推論の求解 | 規則ごとの残り地雷数と未決定数を代入のたびに更新し、規則は確定するときだけ走査します。部分集合規則は数え上げが止まった後に、数が合う組だけ調べます。固定マスだけを見る数字は索引時に一度だけ検査します。未知マスと規則は32×32マスのタイル順に番号付けし、規則の状態は4バイトにまとめます（同じフレームで1ティック270 ms→141 ms） |

2,159ゲートのSnakeは、これらの前は配線が10分以上たっても収束しませんでした（40×32間隔、生成順の配置）。今は配置と配線を合わせて約19秒です。毎ティックの求解は同じフレームで219 msから131 msになりました。

## 検証

| 検査 | 結果 |
| --- | --- |
| コンパイラ対インタプリタ | 19本のサンプルと、全演算子（符号付き除算、変数シフト、キャスト）・制御（関数内の早期`return`、`break`/`continue`、局所配列、変数添字の読み書き、変数座標の`pixel`）の2つの検査プログラムで、到達状態とランダム状態から計5,363,400回の出力比較が一致 |
| ゲームの決まり | 参照インタプリタでランダムなキーを2万ティック与え、Breakoutは玉がブロックに入らず、壊れるのは玉の隣の1個だけで、斜めのブロックは縦と横の隣が空のときだけ壊れること、Snakeは占有格子が体の長さと一致し、頭が首へ戻らず、餌が体に重ならないことを確認（修正前の2本はそれぞれ6、7ティック目で失敗する） |
| エラー | 未定義の名前、入力への代入、定数でないループ条件、再帰、画面外の画素、`;`の不足、入力なし、`while`を行番号付きで拒否 |
| フレーム | 3つの例題で、盤面が通常の推論だけで全マスを確定し、300ティックの表示と状態が参照と一致（Mandelbrotはキーを押さずに728ティック、盤面が1枚の絵を最後まで描く）。2フレームを1枚の通常の盤面として解いた2ティック目の表示も一致 |

参照インタプリタは同じ構文木を64ビット整数と通常の制御フローで実行する独立した実装です。検査だけに使い、生成・求解・表示には使いません。

## 制限

- 1ティックの処理は有限の組合せ回路です。ループは展開できる範囲だけ、再帰はありません。
- ゲートが増えるとフレームも求解時間も大きくなります（目安は1ゲートあたり3,500〜5,500マス、求解は約1,500万マスで0.2〜0.4秒）。
- 入力は6個まで、画面は32×32までです。
